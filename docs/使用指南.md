# 听答使用指南

[返回项目首页](../README.md) · [English](../README.en.md)

## 首次安装与诊断

1. Windows 电脑双击 **安装并启动听答.cmd**（原有 **启动听答.cmd** 也可）。脚本复用可用的 Python 3.12（64 位），缺少时通过 WinGet 为当前账户安装，再创建项目虚拟环境、安装依赖并打开配对页。首次需要联网；实际耗时取决于下载速度，WinGet 可能要求确认软件源条款。没有 WinGet 时会显示官方 Python 安装地址。脚本不改防火墙、不覆盖模型密钥和个人资料。
2. 在电脑配对页点击 **检测设备与连接**：检查后台、系统声音设备、电脑麦克风、回答模型配置、识别配置、局域网地址与控制台连接。手机 **监听设置 → 设备与连接诊断** 可执行同样的检查。
3. 手机与电脑连接同一 Wi-Fi，扫码后进入 **设置**，完成模型与语音识别配置。也可先用电脑的 **预览手机控制台** 完成设置。
4. 先手动提一道问题验证模型，再到 **练习复盘** 录一句话验证麦克风和识别服务。诊断只检查设备枚举和配置，不会录音、截图或请求模型；“配置已填写”不代表密钥、余额、麦克风权限或手机链路已验证。
5. 本机能预览而手机打不开时，双击 **修复手机连接.cmd**，按 Windows 提示允许为此应用添加局域网访问规则；若仍失败，检查访客 Wi-Fi 隔离或重新选择配对页的网络地址。电脑自身无法证明来自手机的连接可达。

安装入口使用 [WinGet 官方安装命令](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)。开发者可执行 `powershell.exe -NoProfile -File install.ps1 -CheckOnly` 只检查 Python，不启动应用、不安装依赖。

## 实际回答与面试复盘

1. 手机打开 **练习复盘**，可直接添加练习题（不请求模型），或选择当前会话中的面试问题。已有回答卡片也有 **练习这道题** 入口。演示数据与屏幕题不进入复盘。
2. 选择 **电脑麦克风**，点 **录我的回答**。采集由电脑执行，手机不申请麦克风权限；默认关闭、重启不恢复。录音固定关联开始时选中的问题，期间出现新问题不会改变归属。可与系统声音监听并行，建议戴耳机避免扬声器回声。
3. 点 **结束录音并转写**，保留最后一段话并等待识别完成。文字逐段追加，再次录音也会追加。单次录音最多 5 分钟；最后的转写最多等待 90 秒，失败时保留已有文字并显示原因。录音期间不能切换题目、编辑回答或生成复盘。
4. 在 **我的回答** 中校正识别结果；也可直接输入实际回答。点 **生成复盘** 会同时保存文字，按岗位和简历评价说清楚的点、遗漏和表达问题，提供改进示例及两个下一轮追问。可将追问复制到 **添加练习题** 继续练习。
5. 复盘调用沿用设置中的回答方式（Codex / Claude Code / 兼容 API），使用独立请求或临时会话。只发送本题、实际回答、岗位与简历，不把 AI 参考稿或其他题的复盘加入输入，也不改变原面试模型上下文。仅根据文字评价，不评价语速、语气或音色。
6. 修改并保存回答后，旧复盘会失效，需要重新生成。**导出复盘** 下载 Markdown，包含生成时的问题、回答和建议。会话最多保留 40 道题，文字与复盘仅存于当前电脑进程内；刷新手机可恢复，清空、重启或更换会清空会话的设置前请先导出。

点击底部 **停止全部** 会立即取消未完成的录音转写和复盘，保留已收到的内容；需要保留最后一句时，请用 **结束录音并转写**。清空会话、撤销配对和退出服务也会释放麦克风并取消后续请求。手机暂时断线后录音会继续，最长至本次 5 分钟上限。

麦克风音频只在内存分段，发送到已配置的识别服务，不写音频文件。转写与复盘会发送至已配对的控制台；云端数据保留和 CLI 运行元数据仍以服务商行为为准。识别和评价可能出错，生成前请校正文字。

## 屏幕解题

1. 更新后重启电脑后台，手机刷新并重新扫码连接，打开 **屏幕解题**。
2. 选择题目所在的显示器，点 **预览并框选**，在手机预览上拖出题目范围；也可选择整块屏幕或输入百分比坐标。预览只发到手机，不请求模型。
3. 选择 **Codex · 已登录账户**（沿用设置中的 GPT 模型），或 **兼容 API · 需支持图片**（沿用设置中的 API 地址、模型与密钥）。屏幕解题无需语音识别密钥；文本模型不能接收截图，目前不通过 Claude Code 处理图片。
4. 选择答案与简短解析、详细步骤或代码说明；可补充“只做第 3 题”“使用 Python”等要求。点击 **单次截图解题** 后，后台重新截取所选区域，答案流式显示在 **回答** 页。
5. 也可以点击 **启用快捷键**，然后在电脑按 **Ctrl + Alt + S**，每按一次截取并解答一次。电脑不会弹出选区窗口、切换应用或播放提示音。启用后固定使用当时的屏幕、范围和解题选项，先关闭快捷键再修改。若快捷键被其他应用占用，会提示改用手机按钮。

### 后台自动监测

在手机选好显示器、题目区域和模型后，点击 **开始自动监测**。电脑每 2 秒检查一次选定区域（可选择 3、5 或 10 秒），先解答当前画面，之后在画面变化且连续两次检查稳定时自动提交。无需反复按快捷键或操作电脑；手机自动切到回答页，底部 **停止** 随时可停止监测并取消当前自动回答。

- 画面比较在本机进行，使用缩小的灰度特征判断变化；只有需要解答时才编码并上传题目截图。最近 12 次提交过的相似画面会跳过，避免频繁调用同一道题；不是精确的题目语义识别，也不保证所有小变化都能识别。
- 生成中继续观察画面，等当前回答结束后处理最新的稳定画面，不积压已经翻过的题目。检测到模型错误或截图失败会停止自动监测，手机显示原因，不持续重试扣费。
- 建议只框选题干、选项与图表，避开倒计时、视频和通知。滚动、选择选项、动画或其他明显变化仍可能触发重新解答。小字改动漏检可提高敏感度，反复触发可降低敏感度或缩小范围。
- 运行时固定监测范围、模型和解题选项；先停止再修改。自动监测会关闭截图快捷键，与声音监听、手动提问和上下文压缩互斥。清空会话、撤销配对、关闭服务都会结束监测；服务重启不会自动恢复。手机暂时断线时电脑仍继续监测，返回后恢复状态。
- 自动提交的截图会发送到所选模型服务并消耗额度。后台运行没有弹窗或提示音，但仍使用普通截图接口，不代表无法被监考软件检测。

快捷键默认关闭，不随重启恢复；只注册这一组按键，不记录其他键盘输入。启用快捷键本身不截图。生成过程中重复按快捷键会被忽略，避免重复请求；手机按钮可提交新截图并取消旧回答。**停止**、清空会话、保存设置、撤销手机配对和退出服务都会关闭快捷键。声音监听与屏幕解题需切换使用，防止声音触发覆盖题目答案。

截图只保留在采集与请求内存中，不写为本地图片文件、不放进问答历史或 WebSocket 推送；自动监测额外保留最多 12 份缩小的灰度特征用于去重，停止后释放。手机预览保留在当前页面内存。自动监测提交、点击单次解题或按已启用的快捷键时，题目截图发送至所选模型服务。Codex 每张截图使用独立的临时会话，结束或取消后关闭；屏幕题不携带简历，也不会混入面试文字历史。CLI 与模型服务自身仍可能记录运行元数据，云端数据保留以服务商政策为准。

屏幕采集使用普通 Windows 截图能力，**不保证不可检测**，不绕过测评软件的截图限制；仅用于允许使用辅助工具的场景。锁屏、受保护窗口或远程桌面断开可能截图失败或得到黑屏；移动/拔插显示器、改变分辨率后需刷新屏幕列表重新框选。支持负坐标副屏与 Windows 缩放，发送图片最长边限制为 2560 像素，预览最长边为 1280；小字建议框选题目区域。题干、选项和图表必须截全，模型仍可能识别或作答错误。

图片输入采用 [Codex App Server 的图片输入接口](https://developers.openai.com/zh-Hans/docs/app-server)；普通截图采用 [Pillow ImageGrab](https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html)，全局快捷键采用 Windows [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

## 现在怎么用

1. 在电脑双击 **启动听答.cmd**，打开配对页：<http://127.0.0.1:8765>。电脑负责后台音频采集、识别和生成。
2. 手机与电脑连接同一个 Wi-Fi，用手机相机扫描二维码。这个链接授予手机控制权限，请只交给自己的设备。
3. 在手机点 **设置**，选择 **Codex CLI · 持续会话**，或 **Claude Code · 本地配置 / DeepSeek**，点击相应检查按钮；选择 MiniMax ASR，填写对应 API Key 并保存（本机已配置时可直接使用）。岗位与个人资料也在手机编辑。
4. 在手机切换到 **监听与上下文**，选择面试软件实际使用的耳机或扬声器，然后点底部 **开始监听**。
5. 切回 **面试回答** 看流式回答；手动补充问题、复制、调字号、停止监听、新建会话、压缩上下文都在手机操作。
6. 配对后可以关闭电脑网页，后台继续工作。结束时在手机点 **停止**，保留当前上下文；需要退出整个电脑服务时，双击 **停止听答.cmd**。

没有配置语音识别密钥也能在手机点 **体验演示**，演示不调用模型、不采集声音。已登录 Codex 时，还可以在手机“补充或修改问题”里手动提问并获得真实回答。

手机刷新后会在当前标签页内恢复连接和问答。暂时断网或息屏不会自动停止电脑采集；返回页面后自动重连。电脑需保持唤醒，且后台进程仍在运行。电脑服务重启或撤销配对后，手机需要重新扫码。

### 两端职责

| 电脑后台 | 手机控制台 |
| --- | --- |
| 采集 Windows 系统声音、调用语音识别与 Codex、推送答案 | 开始/停止监听、选择声音设备、手动提问 |
| 保留当前会话、执行上下文压缩与取消请求 | 查看答案和转写、管理上下文、修改模型与个人资料 |
| 首次启动、Codex 安装/登录、展示和撤销配对二维码 | 扫码连接，配对后完成面试期间的日常操作 |

## 直接回答与简历依据

- 默认输出候选人可以直接说出口的正文，个人经历使用第一人称。多用短句、具体动作和自然衔接，不套固定三段式、教材定义或汇报式总结；普通问题先讲清重点，简单追问一两句，要求详细时再展开，不凑固定字数。不输出“回答思路”“口语示例”或填空模板。
- 手机设置中的“简历与补充资料（系统提示词）”作为事实依据。Codex 模式加入 `thread/start.baseInstructions`；兼容 API 模式加入 `system` 消息。资料按系统上下文发送，不是仅存了一个PDF路径。
- 简历未确认的数据和经历不得编造；不同项目的指标分开使用，在审论文不作为已发表论文。仍应核对模型回答的准确性。
- 在手机设置中填写自己的岗位、教育、实习、项目、成果与技能等面试事实。源码包不包含个人简历；请自行去除与练习无关的联系方式等信息。
- 本机完整系统提示词快照：`%LOCALAPPDATA%\InterviewCompanion\system-prompt.txt`，供查看；运行时使用 `backend/prompts.py` 与手机保存的资料，直接修改该快照不会改变运行配置。
- 常规运行只在内存保留问答，需要留存时请先导出复盘。

## Codex CLI 与上下文

- 通过官方 `codex app-server --stdio` 接口启动独立后台进程，使用 Codex 自己的登录状态与账户额度。不会接入或恢复你在桌面应用中的其他任务。
- 每场面试新建一个 `ephemeral: true` 的内存会话。后续问题向同一会话发送 `turn/start`，由 Codex 保留对话并管理上下文，不再受 API 模式“最近 4 条记录”的限制。
- 手机文字来自 `item/agentMessage/delta` 流式事件；新问题和停止操作会中断上一个正在运行的模型请求。短暂停顿后的续句会合并到同一张问题卡片，再按完整问题重新回答。
- 手机控制台显示已完成轮数、最近一次请求的 token 数、模型窗口大小和已压缩次数。最近请求 token 数用于参考，不是剩余额度，也不是精确的当前内存占用。
- Codex 自身支持上下文压缩；手机控制台的“压缩上下文”按钮可主动触发。请先停止监听并等待回答完成。压缩可能丢失细节，不能当作无限记忆。
- “新建会话”或“清空会话”会结束旧 Codex 进程并清除手机控制台问答；下个问题创建全新会话。更换回答方式、Codex 模型、推理强度或个人资料同样会开始新会话。
- 关闭浏览器页面、停止监听会保留当前 Codex 上下文；退出后台或重启服务后不恢复旧面试。进程异常退出时明确提示上下文丢失，需要新建会话，不会自动假装仍记得旧内容。
- 以只读沙箱运行，关闭 shell、浏览器、插件和继承的 MCP 工具；手机只调用听答提供的限定功能，不直接开放 Codex 原始控制接口。问题通过 JSON 标准输入传递，不拼接进 shell 命令。
- **模型的历史建议不等于你实际说过的话。** 麦克风仅在“练习复盘”手动开始后采集，实际回答单独记录并用于复盘，暂不自动写入原面试回答会话的上下文。
- Windows 下自动从 PATH 或 Codex 桌面安装目录查找 `codex.exe`。找不到时需在电脑修复 CLI 安装或本机配置；手机不能指定任意可执行程序。设置中的“GPT 模型”提供下拉选择，打开设置时从本机已登录的 Codex 读取可选模型，也可手动刷新；选择“沿用 Codex 默认设置”等同于模型留空。读取失败或原模型未出现在列表中时保留原选择，刷新列表不会自动更换模型或清空问答。更换模型后保存会开始新会话，推理强度默认“低”。
- 也支持本机 **Claude Code**，其上下文方式见下一节。

### Claude Code 与 DeepSeek

1. 先在电脑安装并配置 Claude Code；`claude --version` 应能运行。支持原生 `claude.exe` 和标准 npm 安装，启动时直接运行可执行程序，不将问题拼接到 shell 命令。
2. 手机设置选择 **Claude Code · 本地配置 / DeepSeek**，模型可留空。听答读取 `%USERPROFILE%\.claude\settings.json`（或 `CLAUDE_CONFIG_DIR`）内的服务地址、API Key / 认证令牌及模型环境变量；不复制密钥到听答设置，也不回传手机。当前接入使用 API 凭据，不支持仅靠 Claude 订阅 OAuth 登录。
3. 模型优先级为听答填写值 → `ANTHROPIC_MODEL` → Claude Code 顶层 `model`。DeepSeek 使用 `https://api.deepseek.com/anthropic`；若本机写的是 `https://api.deepseek.com`，仅在听答子进程内补齐 `/anthropic`，不改动原配置。
4. **直连模型服务**默认开启，忽略此进程的 HTTP/HTTPS/ALL_PROXY 环境变量，不修改系统代理、VPN 或网卡。系统 TUN/VPN 仍可能影响路由；是否能完全关闭 VPN 使用，取决于电脑能否直接访问已配置的服务。DeepSeek 配置方法见[官方文档](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/claude_code/)。
5. **检查本机 Claude Code**只检查安装和凭据是否存在，不请求模型、不验证密钥有效性。保存后手动提问可验证实际链路。语音识别仍须独立配置。

Claude Code 通过 print 模式流式返回正文。每个问题建立独立调用，携带简历系统提示词、最近 4 条记录中的有效非演示问答及最近 6 条问题原文；不是 Codex 的持续会话，不提供历史压缩。新建会话会清空这些记录。工具、MCP、技能和 hooks 在此调用中禁用，不接入你已有的编程会话。

简历系统提示词写入 `%LOCALAPPDATA%\InterviewCompanion\claude-workspace` 中本次调用的临时文件，结束或取消后删除；异常断电可能留下临时文件。CLI 不保存可恢复会话，但其自身仍可能记录运行元数据。

模型名称、可用性与计费以服务商为准；配置检查通过后，应在自己的环境发出一条测试问题验证真实连通性。

### 后台运行

- **启动听答.cmd**：启动无控制台的后台进程，并打开电脑配对页面。启动脚本自身会短暂出现控制台，完成后关闭。
- **后台启动.vbs**：安装依赖后使用，无控制台、不自动打开浏览器。它只启动服务；开始采集仍需在手机控制台点击“开始监听”。
- **停止听答.cmd**：停止采集、取消请求并退出服务。
- 启动时会检查 `.venv` 能否运行；从其他电脑复制项目导致 Python 路径失效时，会用本机 Python 3.12 修复环境并重新检查依赖。建议迁移项目时不要复制 `.venv`，由启动脚本在新电脑创建。
- 后台运行不会让程序“不可检测”。进程、网络请求和音频采集仍可能被系统或面试软件检测；本项目没有反检测、进程伪装、录屏绕过或屏幕共享隐藏功能。请不要依赖不可检测的假设。
- 没有设置开机自启，也不会在重启服务后自动监听。

## 接入模型

选择“兼容 API”时，应用使用两个独立接口，密钥可以属于不同服务商。配置时填写基础地址，不要附加 `/chat/completions` 或 `/audio/transcriptions`。Codex 模式仅需另行配置语音识别接口。

| 用途 | 接口要求 | 地址示例 | 模型填写方法 |
| --- | --- | --- | --- |
| 回答 | `POST /chat/completions`，支持 `stream: true` 的 SSE 正文输出 | `https://api.deepseek.com`，或服务商提供的兼容地址 | 从服务商控制台复制当前可用的文本对话模型 ID |
| MiniMax 识别 | `POST /speech_to_text`，multipart 文件输入，`response_format=json`，返回 `text` | `https://api.minimaxi.com/v1` | `asr-1.0` |
| 兼容接口识别 | `POST /audio/transcriptions`，multipart 文件输入，返回 JSON `text` 字段 | `https://api.siliconflow.cn/v1` | 默认示例 `FunAudioLLM/SenseVoiceSmall` |
| OpenAI 兼容服务 | 分别满足上述两个接口 | `https://api.openai.com/v1` 或其他兼容 Base URL | 使用账户实际开通且支持相应接口的模型 |

“OpenAI 兼容”在不同服务商间不保证所有参数一致。本项目使用少量通用字段，仍需对具体服务进行验证。只提供文本回答的模型不能同时承担语音识别。兼容 API 模式不会读取其他应用的密钥；选择 Claude Code 时，会按上述方式使用其本机配置。

本机服务允许 `http://localhost:端口` / `http://127.0.0.1:端口`；云端模型接口要求 HTTPS。

### MiniMax + Codex 配置示例

- 识别：MiniMax `asr-1.0`，`https://api.minimaxi.com/v1/speech_to_text`。凭据只保存在本机配置，手机显示“已保存”，不回显密钥。
- 回答：从本机 CLI 的模型列表选择账户当前可用的模型，或沿用 Codex 默认设置。推理强度与 Fast 快速档按需要选择；不同选项的可用性与额度消耗以服务商为准。
- 手机开始监听时先启动 CLI、检查登录并建立独立空会话，完成后开始采集；预初始化本身不发起模型回答。后续问题沿用已建立的会话。
- MiniMax 当前接入的是短文件转写。其 SSE 选项是在文件上传后流式返回文字，不是边采集边传音频；当前使用 JSON 响应配合提前分段。官方接口参考：[MiniMax ASR 调试台](https://solutions.minimaxi.com/debug/asr)。
- 2026-09-15 合成中文音频实测：单独 ASR 4.156 秒；预初始化后的完整链路 ASR 3.547 秒、模型首字 4.110 秒，音频片段就绪到首字 7.657 秒。该时间不含讲话过程和结束停顿，也未包含真实手机网络。一次样本不代表稳定延迟，当前仍存在数秒等待。
- 更短的停顿会提高句中停顿误触发概率；更短的分段增加请求频率和切断词语的概率。先使用 0.5 秒停顿、4 秒分段，根据实测在手机调整。

### 密钥、会话与手机权限

- 模型设置和个人背景保存在 `%LOCALAPPDATA%\InterviewCompanion\settings.json`，是本机明文文件，位于项目目录之外。请保护你的 Windows 账户。
- API Key 不返回给网页，保存后留空表示保留旧密钥。切换服务地址时会清除该服务的旧密钥，避免把旧服务密钥发送给新服务。
- 音频不写入磁盘；按分段上传到你配置的识别服务。API 模式发送个人资料、当前问题、最近 4 条记录中已完成的非演示问答，以及最近 6 条记录的问题原文。Codex 模式将资料和问题发送到独立的持续会话，也明确补充最近问题原文，包括尚未回答或已取消的前半句。云端服务的数据保留政策由服务商决定。
- 手机控制台问答与转写仅在内存保留，分别最多 40 组和 60 条；这只是界面历史的数量上限，不是 Codex 的上下文上限。清空会话同时停止监听与生成，并结束 Codex 会话。
- Codex 使用内存会话，不保存可恢复的面试会话文件；CLI 自身仍可能记录运行元数据。应用不保存 CLI 原始诊断输出。
- 手机通过二维码取得随机控制令牌，保存在当前标签页的 sessionStorage；HTTP 控制请求携带 Authorization 头，WebSocket 在连接后提交令牌。只知道电脑地址无法读取设置或操作。模型密钥不会回传手机，手机可提交新密钥或留空保留旧密钥。
- 配对签发/撤销、退出整个电脑服务仅允许 localhost。电脑“更换二维码并撤销旧手机权限”会停止监听和当前生成，并立即使旧手机的 HTTP 控制权限及 WebSocket 失效。旧版阅读链接不会自动获得控制权限。
- 手机连接是面向可信局域网的 HTTP/WebSocket 原型，不应直接映射到公网。公网版本还需 HTTPS、正式身份认证与设备权限管理。

## 效果与限制

- **接近实时的分段识别**：本机按音量检测说话，本机配置为 0.5 秒停顿先提交识别（新安装默认 1 秒，可在手机调整），连续较长语音每 4 秒先转写一段。问题层另有 2 秒续句合并窗口，按采集时的语音起止时间计算；识别结果到达时若仍在说话、仍有识别请求或音频排队，则继续等候，合并后回答。实际延迟 = 停顿时间 + 转写时间 + 回答模型首字延迟；界面“首字时间”只测量回答模型阶段，“最近音频片段识别”显示该片段上传及识别耗时。积压时还需加上排队时间。
- 这不是语义分句或说话人识别。面试官句中停顿较长时可能提前回答；所选设备的音乐、其他人的语音或通知音也可能触发。
- 使用耳机也能采集所选输出通道的声音，不依赖麦克风听外放。选择“跟随系统默认输出”后，后台约每 2 秒检测默认输出变化并重新打开采集；选择具体设备则固定采集该来源。手机设备列表每 3 秒刷新，监听中也可直接切换来源。切换会有短暂采集间隙，但保留问答、识别队列与模型上下文。蓝牙通话切换通道、独占音频等情况需实测。
- 多声道转单声道时排除空白或极弱声道，严重反相抵消时使用最强声道，避免 Sonar Gaming 等 8 声道来源把左右两路人声平均压低。检测后的语音片段自动补足音量，最多放大 8 倍并保留峰值余量；这不能恢复原本缺失或被噪声覆盖的内容。
- 手机显示实际采集设备、声道数、电平和是否达到检测阈值。设置中的“采集增益”默认 1 倍，只影响采集和识别，不改变耳机播放音量；修正声道后仍漏小声语音时可试 2—4 倍或降低检测阈值。误触发时降低增益或提高阈值，句子被过早截断时提高停顿时间。
- “自动生成回答”可关闭，仅保留转写，再点选文字修改并手动提交。
- 新问题会取消旧回答，保留已收到的正文。识别服务积压或设备断开会停止监听并显示错误。
- 手机应保持网页在前台。手机系统可能在息屏、切换应用时断开连接，返回页面后自动重连并恢复当前会话；不保证手机后台常驻。
- Windows 10/11 + Python 3.12 是本版目标运行环境。Mac、手机直接录音、原生 Android/iOS 安装包和公网服务器部署尚未实现。

## 面试官停顿与连续问题

- “停顿多久提交识别”和“续句合并间隔”是两个独立设置。前者用于尽早转写；后者用于判断是否还有续句。本机保留0.5秒提交识别，默认2秒续句合并，可在手机设置调至0—5秒，0关闭自动合并。
- 合并以实际语音时间间隔为依据，避免ASR网络延迟造成错误分组。若识别回来时续句还在采集或转写，先显示“正在听完整问题”，完成后才调用回答模型。识别耗时与等待续句可重叠，并非识别后固定再等2秒。
- 续句更新原卡片的完整题目，显示“已合并N段”；前半句若已开始回答，会中止旧生成，按完整题目重新生成。
- 间隔较长或明确说“下一题”“换个问题”时，新建卡片；模型仍收到最近问题原文，保留场景、对象、指标等限制。比如“安防摄像头的光学设计”后接“光学系统需要怎么设计”，回答应继续围绕安防摄像头。
- 这是基于时间的合并规则与模型上下文理解，不是精确的语义分句或说话人识别。两道独立问题间隔很短时仍可能误合并，可调低合并间隔；停顿较长可调高。手动提问视为明确提交，停止监听会取消尚未自动提交的内容。

## 手机连不上时

1. 确认手机和电脑在同一个 Wi-Fi，避免访客网络或 AP 隔离。
2. Windows 防火墙可能阻止手机访问，尤其是当前 Wi-Fi 被标记为“公用网络”时。可使用项目的 `repair-phone-access.ps1` 添加或更新局域网访问规则；需允许管理员确认。脚本会核对监听进程确属本项目，并将来源限制为本地子网，防火墙保持开启。
3. 如果电脑有多个网络地址，选择 Wi-Fi 对应地址后再扫码。
4. 手机输入 `http://电脑Wi-Fi地址:8765/health`，正常应显示 `ok: true`。若打不开，先排查网络与防火墙。
5. 连通但连接码失效，重新扫描电脑配对页的最新二维码。电脑重启后旧码不再有效。
6. 电脑睡眠会中断服务；面试期间保持电脑唤醒。

## 启动方式变化后的手机连接修复

启动器使用的 Python 解释器发生变化后，旧防火墙规则可能不再匹配。连接修复脚本会针对实际解释器更新规则，来源限制为本地子网，防火墙保持开启；首次安装不会自动修改防火墙。

手机无法打开时，在当前运行项目所在文件夹双击“修复手机连接.cmd”，允许Windows管理员确认，完成后刷新手机页面。修复会识别实际监听进程及Python安装路径，同时更新python.exe/pythonw.exe规则；不会清空会话或重启已运行的服务。若移动或重新安装Python，可再次运行修复。脚本要求当前监听服务属于该项目目录，多网络时会停止并提示先选择网络。
